You build AgentHub's interface. Read `docs/design-system.md` before writing CSS and
`docs/architecture.md` §6 before touching state.

## Rules that fail build or review

- **Zero raw color values.** Only tokens from `src/styles/tokens.css`. A `#` in a
  component is a bug.
- **Zero pixel values** outside the scale (4, 6, 8, 12, 16, 24, 32) and outside the
  dimensions fixed in design-system §4.
- **Zero hand-written TypeScript** mirroring a Python model. Only
  `src/api/schema.d.ts` and `src/api/events.d.ts`, generated by `pnpm gen:api`.
- **Zero `any`.** `strict` + `noUncheckedIndexedAccess` are on.
- No `export default`, no barrel files.

## State: three sources, never mixed

| Source | Tool |
|---|---|
| Server (sessions, graphs, history) | TanStack Query — never copy into a local store |
| Live (events, metrics, PTY) | **one** WebSocket connection → Zustand store |
| UI (open drawer, zoom, filter) | `useState` / local store, never persisted server-side |

A single WebSocket connection for the whole app, multiplexed by topic
(`session:<id>`, `run:<id>`, `metrics`). One per panel overloads the backend and
produces divergent event ordering between components.

A structural event (node completed, merge happened) **invalidates a query**. A
stream event (text delta, PTY chunk) **updates the store**. Confusing the two
causes flicker or stale state.

## Performance is a functional requirement here

The app receives hundreds of events per second with several nodes running.

- **Always a narrow selector.** `useGraphStore(s => s.nodes[id]?.status)`, never
  `useGraphStore()`. A broad selector freezes the tab.
- **`GraphNode` is `React.memo`.** The ELK layout runs only when the topology
  changes — not on every event.
- **`TerminalPane` mounts xterm once in a ref and never re-renders.** Writing is
  `term.write()`, not React.
- **`EventFeed` is virtualized** (`@tanstack/react-virtual`) past ~200 rows.
- `useEffect` only to sync with an external system (WS, xterm, ELK,
  `ResizeObserver`), always with cleanup. Never to derive state.

## Components

From shadcn: install with `pnpm dlx shadcn@latest add <name>`, tune the density
once in `src/components/ui/`, not per call site.

Custom: only when the same arrangement appears a third time. Before that, inline
composition in the route. Inventory in design-system §8.

A component in `routes/` fetches data and passes it down. A component in
`components/` receives props and knows nothing about the API.

## Product rules that surface in the UI

- Cost is **"estimated equivalent"**, never "spend", when the harness runs under a
  subscription.
- Token bars stack in the order `cache_read → cache_write → input → output`.
- Node state is color **+ icon + label**, never color alone.
- Every code-search claim cites a clickable `path/to/file.py:123`.
- The planner's graph is an editable proposal: nothing runs before approval.
